# Precision diagnostic: what is and is not available

The uploaded repository does **not** contain the old failing regular-load P2
H1 convergence history or a dated pre-fix source revision. A historical P2
old-versus-corrected convergence overlay cannot be verified from this archive.
The canonical corrected figures are kept in their own final directory.

## Reproducible controlled P2 example

```bash
python -m experiments.validation.solvers.precision_review
```

This small check uses f=1, psi=-1 and u=x(1-x)/2, which belongs to the P2 FE
space on every mesh. It compares `solve_on_active_set` (retained binary64
physical-coordinate implementation) with `solve_gap_p2_on_active_set` on
identical meshes and an empty contact set. It records actual H1 errors.
At 23 elements and h_min approximately 1e-9, errors are about 1.12e-8 and
9.53e-12, respectively. This is not a reconstruction of the missing history.
The sweep changes mesh grading, not a standard nested convergence sequence.

Files: `results/validation/submission/p2_precision_controlled.csv` and
`figures/presentation/precision_controlled.png`. The five-line literal excerpt
in `presentation/precision_excerpt.py` comes from
`src/p2_nested_large.py:467`–471 and is regenerated by
`python -m presentation.make_figures`.

German explanation: „Die Koeffizienten des reduzierten Systems werden aus den
Elementlängen in höherer Präzision aufgebaut und mit höherer Präzision gelöst.
Das diskrete Problem bleibt gleich. Die Rückgabe erfolgt weiterhin als
binary64; Rundungsfehler verschwinden deshalb nicht vollständig.“

## Authentic P1 before/after evidence from this review

The original regular adaptive P1 curve is preserved in `pre_precision_fix/`.
The broadened precision trigger removes its spurious L2 increase. The
same-mesh fixed-active-set check and complete rerun agree at the last point:
4.41e-10 before, 8.61e-12 after. This is an L2 comparison, not the missing
historical P2 H1 plot. See `figures/presentation/p1_l2_before_after.png`.

## Safe procedure if the old P2 revision is recovered

1. Recover its exact commit and failing CSV from local Git history/backups.
2. Create two isolated worktrees/directories. Never run the old code against
   `results/key/inner_study/budget_300000/` in the submission checkout.
3. Reproduce the old mesh sequence and save it. On each identical mesh, compare
   the same fixed active-set equations in ordinary and higher precision.
4. Evaluate both solutions with the same stable gap-based error routine and
   the same split quadrature/reference. Check nodal KKT and derivative errors.
5. Save both source hashes, mesh hashes, precision settings and diagnostic CSVs.
6. Plot under `figures/presentation/precision_diagnostic_historical.png`, with
   the recovered revision and date in the caption. Keep this separate from
   canonical final convergence figures.

For the talk, the precision example is a better main implementation story than
listing Thomas code: it links a visible accuracy problem to mathematical
conditioning and verification. Thomas and static condensation remain backup
questions; do not say that the diagnostic proves one universal cause.

## Retained P2 uniform L2 irregularity

`python -m experiments.validation.solvers.precision_review --p2-uniform`
re-solves the last three fine problems using the current higher-precision path,
with an analytic-reference initial guess used only in this diagnostic. It
reproduces the stored L2 increase from 4.69e-11 to 6.48e-11 and the final
4.10e-13 value. This is compatible with free-boundary alignment effects and
no L2 monotonicity theorem; it is not automatically a rounding failure.
The final study still uses only coarse-grid Riesz initializations.
